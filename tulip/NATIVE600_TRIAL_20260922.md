## Pending-work watchdog follow-up

Implemented a distinction between an idle client and stalled asynchronous processing. The WebSocket session now counts native queued chunks plus RIFE/upscaling/presentation work. The 10-second idle deadline applies only after work drains. Outstanding work instead has a bounded 120-second no-progress deadline on Tulip (derived from existing processing/first-frame settings). Native stage completion, output and presentation completion count as progress; merely sending more input cannot keep a stalled worker alive indefinitely. A processing timeout emits an error with a bounded worker-stack snapshot instead of misreporting client idleness.

The worker stack captured in guarded-195556 confirms coordinate-descent autotuning inside the compiled second-chunk VAE decoder. The generated Inductor graph declares an FP32 latent input. StreamingGraphRunner.run_full returns FP32 scheduler accumulations, whereas warmup_decode previously allocated latents in the BF16 VAE compute dtype. Added an independent input_dtype argument and warmed FP32 inputs when CUDA graphs are enabled, retaining the BF16 autocast compute precision. Inference arithmetic is unchanged. Two warm-up precision tests and two existing VAE policy tests passed.
